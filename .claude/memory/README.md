# Memory Directory

This directory stores debugging state and tracking information that is **user-specific** and **gitignored**.

## Purpose

Separate debugging state (memory) from product decisions (product-guidelines):

- **product-guidelines/**: Product cascade outputs (committed to repo)
- **.claude/memory/**: Debugging tracking state (gitignored, user-specific)

## Contents

### Tracking Files

Generated by `/fix-bug` command:

- `issue-{number}-attempts.json`: Per-issue debugging attempt history
- `pr-{number}-attempts.json`: Per-PR failure tracking (alternative naming)

**Structure:**
```json
{
  "issue_number": 123,
  "attempts": [
    {
      "round": 1,
      "hypothesis": "Missing null check in validateUser()",
      "fix_applied": "Added if (!user) return null",
      "test_result": "FAILED",
      "error_signature": "TypeError-undefined-parser:42",
      "error_type": "TypeError",
      "error_message": "Cannot read property 'x' of undefined",
      "error_location": "src/parser.js:42:15",
      "timestamp": "2026-01-31T10:15:00Z"
    }
  ],
  "error_counts": {
    "TypeError-undefined-parser:42": 3
  },
  "escalation_triggered": false,
  "status": "in_progress"
}
```

### Metrics (Optional)

Optional file for tracking debugging effectiveness:

- `metrics.json`: Aggregate debugging metrics

**Structure:**
```json
{
  "bugs_resolved": 42,
  "mean_attempts": 2.3,
  "hypothesis_hit_rate": 0.43,
  "escalation_rate": 0.28,
  "pr_spam_reduction": 0.82
}
```

## Lifecycle

### Creation

- Created automatically by `/fix-bug` on first attempt for an issue
- Each issue gets its own tracking file

### Updates

- Updated after EVERY debugging attempt (pass or fail)
- Managed by Failure Tracking Agent

### Cleanup

- Persists across PR closure (unlike GitHub PR comments)
- Can be manually deleted when debugging complete
- Not committed to repo (gitignored)

## Why Separate from product-guidelines?

| Aspect | product-guidelines/ | .claude/memory/ |
|--------|-------------------|-----------------|
| **Purpose** | Product decisions | Debugging state |
| **Audience** | Humans + AI | AI only |
| **Lifecycle** | Permanent (cascade outputs) | Temporary (per-bug) |
| **Version control** | Committed to repo | Gitignored |
| **Shareability** | Team-wide | User-specific |

## Recovery

If tracking files are lost or corrupted:

1. `/fix-bug` will create fresh tracking file
2. Previous attempts may be recovered from GitHub issue comments
3. Debugging can resume from current state

## Privacy

- Contains error messages and code locations (no secrets)
- Safe to share for debugging assistance
- Automatically excluded from repo (gitignored)
