**Issue Number:** $1

## Your Task

Implement the issue following the approved plan exactly. Execute with precision, zero creativity.

## Step 1: Fetch Issue and Approved Plan

**Get issue details:**
```bash
gh issue view $1 --json title,body,labels,comments
```

Or for GitLab:
```bash
glab issue view $1
```

**Find the approved plan:**

Look for a comment that starts with "# 🧭 Plan for" or contains "Implementation Plan".

The plan was generated by `/plan-issue` and contains:
- Journey context and user value
- Product guidelines context (already loaded)
- Technical approach with specific steps
- Files to change
- Success criteria

**CRITICAL - Do NOT Re-Read Product Guidelines:**

The `/plan-issue` command already analyzed and included ALL relevant product-guidelines context in the plan's "Product Context & Guidelines" section. Everything you need is in the plan.

**DO NOT:**
- Read `product-guidelines/` files during implementation
- Search for additional context beyond the plan
- Second-guess the plan's guidelines references

**DO:**
- Trust the plan completely
- Follow it exactly as written
- Use the context already embedded in the plan

**If no approved plan exists:**

STOP immediately and output:
```
❌ No approved plan found for issue #$1

This issue needs a plan before implementation.

**Next steps:**
1. Run: /plan-issue $1
   OR
2. Add "needs-plan" label and wait for GitHub Action
   OR
3. Comment "@claude-plan" on the issue

After plan is posted and reviewed, run /implement-issue $1 again.
```

## Step 2: Create Issue-Linked Branch

**Create branch from issue number:**
```bash
git checkout -b $1-{kebab-case-issue-title}
```

Example: `git checkout -b 42-add-document-upload`

**Ensure branch name starts with issue number** for automatic GitHub/GitLab linking.

## Step 3: Execute Implementation Plan

**Follow the plan's "Implementation Steps" section EXACTLY:**

For each step in the plan:

1. **Announce the step**: "Implementing step X: [description]"
2. **Make the change**: Edit/Write files as specified
3. **Verify syntax**: Check for obvious errors
4. **Run tests**: Execute relevant test suite
5. **Mark complete**: Move to next step

**Surgical Precision Rules:**

- ✅ Only touch files listed in plan
- ✅ Make minimal changes
- ✅ Follow plan's technical approach exactly
- ✅ Use plan's context (don't seek additional context)
- ❌ Don't refactor outside scope
- ❌ Don't add "improvements" not in plan
- ❌ Don't deviate from steps
- ❌ Don't read product-guidelines (context is in plan)

**If ANY step fails:**
- STOP immediately
- Report failure with full error details
- Ask user: "Plan step X failed. Should I: (1) Debug and continue, (2) Stop and revise plan?"

## Step 4: Run Full Test Suite

After completing all implementation steps:

```bash
# Run tests (adjust to your project)
npm test            # Node.js
pytest              # Python
go test ./...       # Go
cargo test          # Rust
```

**Also run:**
```bash
# Linting
npm run lint

# Type checking
npm run type-check  # or tsc --noEmit, or mypy
```

**All must pass.** Fix any failures before proceeding.

## Step 5: Verify Success Criteria

Check each success criterion from the plan. Provide evidence:

```markdown
✅ Criterion 1: {evidence - test output, screenshot, API response}
✅ Criterion 2: {evidence}
❌ Criterion 3: {failure reason}
```

**If any criterion fails, implementation is incomplete.**

## Error Handling

**If no approved plan found:**
- STOP and ask user to run `/plan-issue $1` first
- Don't attempt implementation without plan

**If implementation cannot be completed:**
- Commit partial work to feature branch with WIP marker
- Document blockers clearly
- Update issue with status comment
- Ask user for guidance

**Never:**
- Leave uncommitted changes
- Create PR with failing tests
- Deviate from approved plan without asking
- Commit untested code
