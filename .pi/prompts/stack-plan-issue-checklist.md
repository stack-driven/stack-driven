# Spec-Driven Planning Checklist

Use this before drafting an issue plan.

- [ ] The issue has a clear user value or journey step.
- [ ] Candidate specs are identified from `specs/manifest.yaml`.
- [ ] Only relevant `.ctx.md` summaries are loaded first.
- [ ] Full specs are loaded only if summaries are insufficient.
- [ ] Missing or stale specs are flagged before implementation.
- [ ] Non-goals are explicit.
- [ ] Acceptance criteria are measurable.
- [ ] An implementation outline is written.
- [ ] Validation evidence is defined.
- [ ] Whether specs need updates first is answered.
- [ ] The plan traces back to authoritative spec paths.
