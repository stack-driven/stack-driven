# Validation Examples - ComplianceFlow

This directory contains example validation checkpoints for the ComplianceFlow compliance-saas example.

## What's Here

### Customer Discovery Validation
- `00-user-journey-validation.md` - Results from 12 customer interviews
  - Shows how validation confirmed the pain point
  - Documents journey adjustments based on feedback
  - Demonstrates 8.5/10 validation score (passing gate)

## Purpose of These Examples

These files demonstrate:

1. **What good validation looks like**
   - Specific participant details (roles, companies, pain scores)
   - Direct quotes from interviews
   - Quantified value (ROI calculations)
   - Evidence of willingness to pay

2. **How to document findings**
   - What validated vs what was learned/adjusted
   - Journey changes based on customer feedback
   - Why the validation score is X/10
   - Clear pass/fail gate status

3. **Honest assessment**
   - Not claiming perfection (8.5/10, not 10/10)
   - Acknowledging unknowns (competitive landscape)
   - Documenting what would increase confidence

## How to Use These

**DO:**
- Use as a template for YOUR validation documentation
- Notice the level of specificity (12 interviews, specific quotes, math)
- See how assumptions changed based on real feedback

**DON'T:**
- Copy these verbatim (your interviews will be different!)
- Fake validation (be honest about your score)
- Skip validation because "example did it" (you still need real customers)

## Validation Philosophy

These examples show that:
- **Validation is NOT a checkbox** - it's deep customer understanding
- **Adjustments are expected** - all journeys change based on feedback
- **Evidence matters** - not "I think", but "12 people said..."
- **Gates exist for a reason** - if score <7/10, pause and re-interview

## Questions About These Examples?

If you're unclear on:
- How to run customer interviews → See `output/00-interview-guide.md` (generated by /refine-journey)
- How to score validation → See acceptance criteria in `.claude/commands/refine-journey.md`
- What to do if validation fails → See "If score <7/10" section in refine-journey command

---

**Remember**: These are examples from a B2B SaaS context. Your interviews will be different if you're building:
- Consumer apps (different personas, different willingness to pay)
- Enterprise tools (longer sales cycles, more stakeholders)
- Free/open-source (validation is usage, not payment)

Adapt the validation approach to YOUR context, but keep the rigor.
