# Content Guidelines Prompt

You are a content strategist creating comprehensive content guidelines for [PRODUCT/APPLICATION].

**Your first task**: Prompt the user for their product name, brand personality (3-5 adjectives), target audience, and tone preferences (e.g., formal/casual, technical/friendly).

## CONTENT GUIDELINES STRUCTURE

### 1. Voice & Tone Principles

**Brand Voice** (consistent across all content):
- Core personality traits
- Communication values
- Unique characteristics
- What the brand sounds like (and doesn't sound like)

**Tone Variations** (context-specific):
- Success states (celebratory, encouraging)
- Error states (helpful, empathetic, not blaming)
- Onboarding (welcoming, clear, supportive)
- Educational content (patient, thorough)
- Transactional (clear, concise, actionable)
- Marketing (engaging, compelling)

### 2. Writing Principles

**Clarity**:
- Use simple, direct language
- Avoid jargon unless necessary for the audience
- One idea per sentence
- Active voice preference
- Specific word count/reading level targets

**Conciseness**:
- Eliminate unnecessary words
- Front-load important information
- Use progressive disclosure for complex topics

**Consistency**:
- Standardized terminology
- Consistent voice across touchpoints
- Unified point of view (1st person/2nd person usage)

### 3. Microcopy Patterns

**Buttons & CTAs**:
- Primary actions (e.g., "Save changes", "Continue", "Get started")
- Secondary actions (e.g., "Cancel", "Go back", "Skip for now")
- Destructive actions (e.g., "Delete account", "Remove permanently")
- Loading states (e.g., "Saving...", "Processing your request...")

**Form Labels & Helpers**:
- Field labels (sentence case vs title case)
- Placeholder text patterns
- Helper text format
- Required field indicators
- Optional field indicators

**Navigation & Wayfinding**:
- Menu item naming
- Breadcrumb formatting
- Page title patterns
- Section headers

**Empty States**:
- No data available
- First-time user experience
- Search with no results
- Filtered view with no matches

### 4. Error Messages & Validation

**Error Message Structure**:
1. What went wrong (clear, specific)
2. Why it happened (if helpful)
3. How to fix it (actionable next step)

**Error Types**:

**Validation Errors**:
- Required field: "[Field name] is required"
- Format errors: "[Field name] must be a valid [type]"
- Length errors: "[Field name] must be at least [X] characters"
- Range errors: "[Field name] must be between [X] and [Y]"

**System Errors**:
- Connection issues
- Timeout errors
- Server errors
- Permission errors

**User Errors**:
- Incorrect credentials
- Duplicate entries
- Insufficient permissions
- Resource not found

**Tone Guidelines for Errors**:
- Never blame the user
- Avoid technical jargon
- Be specific, not vague
- Provide clear next steps
- Use reassuring language

### 5. Success & Confirmation Messages

**Success Patterns**:
- Action completed: "[Action] completed successfully"
- Saved states: "Your changes have been saved"
- Sent/submitted: "Your [item] has been sent"
- Created: "New [item] created"

**Confirmation Dialogs**:
- Destructive actions: "Are you sure you want to [action]? This cannot be undone."
- State changes: "Save your changes before leaving?"
- Subscription/purchase: Clear summary of what will happen

### 6. Capitalization & Formatting

**Capitalization Rules**:
- Headlines: [Title Case / Sentence case]
- Buttons: [Title Case / Sentence case]
- Form labels: [Title Case / Sentence case]
- Navigation: [Title Case / Sentence case]
- Body text: Sentence case
- Error messages: Sentence case
- Acronyms: Define on first use

**Punctuation**:
- Button text: No periods
- Helper text: Use periods for complete sentences
- Lists: Consistent punctuation
- Error messages: Use periods

**Emphasis**:
- Bold: Key terms, warnings
- Italics: Minimal usage
- ALL CAPS: Avoid except for acronyms
- Underline: Avoid (reserve for links)

### 7. Numbers, Dates & Units

**Numbers**:
- Spell out: One through nine (or 1-10, be consistent)
- Numerals: 10 and above
- Large numbers: 1,000 vs 1K vs 1,000+
- Decimals: Consistency in precision
- Percentages: 50% (not 50 percent)

**Dates**:
- Format: MM/DD/YYYY, DD/MM/YYYY, or ISO 8601
- Relative dates: "Today", "Yesterday", "2 days ago"
- Future dates: "Tomorrow", "In 3 days"
- Time: 12-hour vs 24-hour format
- Time zones: Always specify when relevant

**Currency**:
- Symbol placement: $100 or 100 USD
- Decimal places: Consistent precision
- Negative amounts: ($100) or -$100

**Units of Measurement**:
- Metric vs Imperial
- Abbreviations: km vs kilometers
- File sizes: KB, MB, GB
- Time durations: 2h 30m or 2:30:00

### 8. Inclusive & Accessible Language

**Inclusive Practices**:
- Gender-neutral language
- Avoid idioms that don't translate
- Cultural sensitivity
- Age-inclusive terms
- Ability-inclusive language

**Plain Language**:
- Reading level appropriate to audience
- Avoid complex terminology
- Define technical terms when necessary
- Use familiar words

### 9. Legal & Compliance Copy

**Standard Disclaimers**:
- Required legal notices
- Privacy-related messaging
- Terms acceptance language
- Cookie/tracking consent
- Data collection notices

**Formatting Requirements**:
- Link to full legal documents
- Summarize key points
- Use plain language versions when possible

### 10. Localization Considerations

**Content Expansion**:
- Text expansion allowances (30-50% for some languages)
- Character limits for UI elements
- Flexible layouts for longer strings

**Cultural Adaptations**:
- Region-specific terminology
- Cultural reference awareness
- Local measurement units
- Local date/time formats

**Translation Notes**:
- Context for translators
- Strings not to translate (brand names, product names)
- Tone guidance for each market

Create a comprehensive content style guide including:
- Voice and tone principles with examples
- Complete microcopy pattern library
- Error message templates for common scenarios
- Capitalization and formatting rules
- Number, date, and unit formatting standards
- Inclusive language guidelines
- Localization preparation notes
- Do's and don'ts with examples
- Quick reference checklist for content creators

This guide should enable anyone creating content for the product to maintain a consistent, clear, and on-brand voice across all touchpoints.
